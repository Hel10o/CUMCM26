# 有限程序复用改进与实际验证

## 1. 已证实的问题与修改边界

旧run_all.py在resume时主要比较输入哈希，并以状态中的passed或NPZ／JSON是否存在决定复用。修改物性、边界、积分配置或源码后，仍可能复用旧结果；任意非空目录只要没有run_state.json，也并非完整地受到保护。

这不否定本地9月11日的新目录十阶段验收。本轮只在 `runtime/` 新副本修改入口管理，并增加 `source/q2_run_guard.py`；所有原科学算子、时间积分、Richardson、谱解、二维方程、导出和论文生成源文件均按原字节复制。

## 2. 已实现的最小安全约束

| 约束 | 实现 | 实际验证 |
|---|---|---|
| 源码／配置绑定 | 每阶段绑定相关源码、整个入口、管理器、输入及Python/NumPy/SciPy版本；入口哈希包含硬编码网格、容差、时域；额外配置字典亦纳入 | 物性源码、时域入口、额外配置及环境变化均使相关缓存失效 |
| 阶段依赖 | assemble依赖六个计算／测试阶段，export和report依赖assemble，audit依赖结果／Excel／正文 | 依赖缺失拒绝汇总；上游文件损坏使下游失效 |
| 绘图不触发无关计算 | report源码只进入report及audit签名 | 只改q2_report.py，数值阶段仍可复用 |
| 模板局部失效 | 模板哈希与导出引擎纳入excel，传给audit | 模板变化只使excel和audit失效 |
| 完整阶段复用 | 只有完整阶段及所有输出哈希匹配才复用；不凭单个NPZ存在续算 | 中断／失败阶段不复用，篡改文件不能通过 |
| 输出保护 | 拒绝输入、源码、第一问、已验收第二问／审核树、任意未管理非空目录；检查解析后路径及内部符号链接 | 覆盖、符号链接绕过、复制归属标记、legacy缓存均被拒绝 |
| 明确合法续算 | 新目录由schema=2标记绑定绝对输出目录及run ID；必须显式--resume | 同源未变完整阶段可正常跳过 |

配置变化不是靠手写“模型版本字符串”识别，而由执行源码字节、入口中的实际配置和相关依赖共同约束。修改入口会保守地使全部阶段失效；只改独立绘图文件不会。依赖映射是显式的，未来新增模块必须同步登记其依赖，不能宣称对任意未来插件自动安全。

失败阶段从该阶段起点重新运行，不复用原二维阶段的无签名内部checkpoint。这样少了细粒度中断恢复，却避免把未验证的旧状态接到新模型；本轮优先保证可追溯性，不建设复杂的任务调度系统或自动迁移旧缓存。

## 3. 实际执行与范围

`tests/test_run_guard.py`的 **26项**测试均通过，包括真实的两次60s、40区间核函数计算。原与副本温度、含水率的未舍入数组最大差均为0，核心源码SHA256一致；该计算只验证管理修改未改算子，不替代3h物理模型验收。

另外真实运行了新入口的tests阶段，返回0；随后同目录合法resume输出REUSE VERIFIED tests而未重新计算。未带resume写非空目录，以及尝试把输出写进已验收结果目录，都实际返回拒绝。记录见 `tests/results/entry_integration.json`。

本轮没有运行新入口的全十阶段流程，没有新增3h主数值解或重新导出正式Excel。原十阶段、独立Radau及全部453600值一致性来自被复用的验收证据；不能把管理测试中的文本夹具说成真实数值参考解。

## 4. 使用方式

在本包根目录可先执行管理与核函数回归：

```bash
python -m pip install -r requirements.txt
python tests/test_run_guard.py
python tests/check_entry.py
```

`check_entry.py`在临时新目录实际运行tests阶段并记录合法／非法续算行为。它会更新本包自己的tests/results，不触碰原已验收目录；输出中COMPLETE: False是只执行一个阶段的正常状态，不是十阶段计算失败。

未来确需新完整计算时，使用本包中的新副本和新的输出目录：

```bash
python runtime/run_all.py --out work_new --excel-engine portable
python runtime/run_all.py --out work_new --excel-engine portable --resume
```

上面完整计算命令是可运行入口说明，**本轮未用它运行all阶段**。程序拒绝把旧交付目录作为合法缓存接管；不要仅将patch直接写入原q2_final_delivery再运行默认输出，保护机制会拒绝该目录树。

`patches/run_all.patch`和`patches/q2_run_guard.py`提供最小源码差异；优先直接使用已给出的runtime完整新副本。Windows不必安装patch命令；数值依赖沿用现有版本，portable不需要artifact_tool。
